# 用内置配置快速添加 App 分流

[返回首页](../README.md) · [English](app-routing.en.md)

**v0.1.5 开发版预览。** v0.1.4 尚未包含这套内置方案；正式发布后请使用 v0.1.5 或更新版本。下图来自 Android 模拟器的实际界面，订阅、节点和连接使用演示数据，不是可用线路或测速结果。

你只需要导入自己的订阅、绑定“应用分流规则”，再从连接详情把 App 加入 **直连 / 代理 / 屏蔽**。不需要自己编写 YAML，也不需要手动创建策略组。

## 1. 给订阅绑定“应用分流规则”

进入 **订阅**，展开订阅管理面板，在目标订阅卡的 **配置** 行点击 **绑定**，选中 **应用分流规则**，点击 **保存**。保存后，卡片的配置行会显示这个名称。

<p>
  <img src="../assets/images/app-routing/01-bind-config.png" alt="步骤 1：在配置绑定弹窗中选择内置应用分流规则并保存" width="310">
  <img src="../assets/images/app-routing/02-subscription.png" alt="保存后的订阅卡显示应用分流规则，下方显示代理选择器" width="310">
</p>

这个方案使用“完全重建”：保留订阅节点及节点提供者，用内置方案重建规则和策略组。它带有 **🚀 代理选择器**，以及三份初始为空的规则集。没有命中分流规则的连接最终交给代理选择器；主页的局域网绕过规则仍然优先。

本地配置与本地脚本互斥；如果这张订阅卡原来绑定了脚本，改绑配置会替换该绑定。订阅的“漏网之鱼”保持 **跟随配置**，才能沿用方案的默认出口。

## 2. 选择规则模式，开启应用识别

回到 **主页**，选择 **规则**。展开 **运行参数 → 基础设置**，把 **进程匹配** 改为 **始终匹配**，点击 **保存**。

<p>
  <img src="../assets/images/app-routing/00-home.png" alt="主页选择规则模式，运行参数面板位于控制卡下方" width="310">
  <img src="../assets/images/app-routing/03-process-mode.png" alt="基础设置中的进程匹配选择始终匹配，然后保存" width="310">
</p>

初始三个规则集都是空的，默认的“按需匹配”可能不会查询应用包名，因此这一步有助于从连接详情添加 App。系统仍可能无法提供某些连接的应用归属；“始终匹配”不能绕过 Android 的限制。

在订阅页的 **🚀 代理选择器** 中选好节点，然后启动代理并同意 Android VPN 授权。已经运行时，点击页面顶部的重启按钮应用刚保存的设置。

## 3. 打开 App，让连接出现

打开你要分流的 App，访问一个页面或刷新内容，再回到 Jeemi 的 **更多 → 连接**。点击对应连接行，或右侧的详情图标。

<p>
  <img src="../assets/images/app-routing/04-connections.png" alt="连接列表中的示例浏览器连接，可点击连接行或详情图标" width="310">
  <img src="../assets/images/app-routing/05-connection-details.png" alt="连接详情显示应用包名 com.android.chrome，包名一行右侧有添加规则按钮" width="310">
</p>

要让**整个 App** 使用同一种出站，点击 **应用包名** 右侧的 **添加到规则集**。例如图中的 `com.android.chrome`。不要选择“目标”或“目标地址”一行，它们分别用于域名或 IP 分流。

截图使用离线演示连接，所以列表显示未运行状态。实际使用应先启动代理；连接页只观察在该页前台可见时采集到的连接，不保证保留短连接或后台历史。没看到目标 App 时，可以再产生一次请求后返回查看。

## 4. 选择直连、代理或屏蔽

在 **添加到规则集** 窗口核对包名，打开 **本地规则集**，选择已有的目标集合。

| 选择哪个规则集 | 保存并重启后的去向 |
| --- | --- |
| **直连** | App 的匹配连接使用 `DIRECT` |
| **代理** | App 的匹配连接交给 **🚀 代理选择器** |
| **屏蔽** | App 的匹配连接使用 `REJECT`，请求被拒绝 |

<p>
  <img src="../assets/images/app-routing/06-select-ruleset.png" alt="规则集下拉菜单包含直连、代理、屏蔽三个现成集合" width="310">
  <img src="../assets/images/app-routing/07-rule-preview.png" alt="选择直连后预览 PROCESS-NAME,com.android.chrome，确认后保存" width="310">
</p>

图中将 Chrome 加入 **直连**。下方会自动预览 `PROCESS-NAME,com.android.chrome`，确认目标集合和包名后点击 **保存**。

优先选择这三份已关联的规则集。如果选择“新建规则集”，还需要在策略组中引用它，单独新建并保存不会自动接入分流方案。包名入口会优先展示开启 App 列表的规则集，仍需核对选择，不能把默认选中当作自动判断去向。

## 5. 在 App 列表确认，重启后使用

进入 **配置 → 本地规则集 → 直连**，可以看到刚加入的 App。默认开启的 **App 列表** 会显示已安装应用的图标、名称和包名；可以排序、删除，或通过 **添加 App** 继续添加应用。

<img src="../assets/images/app-routing/08-app-list.png" alt="直连规则集的 App 列表显示 Chrome 的图标、名称和包名，以及排序和删除按钮" width="340">

最后点击页面顶部的 **重启** 按钮，让当前代理使用新规则；停止状态则直接启动。重新在目标 App 中发起连接，再到连接详情确认命中规则及实际出口。保存修改不会立即改变现有代理会话。

## 改变去向时，记得移除旧规则

“添加规则”是追加，不会把同一个 App 从其他集合自动移走。例如想把 Chrome 从直连改为屏蔽，应删除 **直连** 中的旧条目，再加入 **屏蔽**，保存后重启。

默认匹配顺序为：**主页局域网绕过 → 屏蔽 → 直连 → 代理 → MATCH（代理选择器）**。重复命中时使用先匹配到的规则；全局或直连模式不会按这套规则逐条分流。

没有包名时可以使用域名/IP 规则，或在规则集的 **添加 App** 中主动选择已安装应用。内置资源可编辑、可删除，只初始化一次；删除后不会在每次启动时自动恢复。
